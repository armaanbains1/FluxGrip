# fluxGrip

fluxGrip is an embedded workout tracking system built around an MPU6050 inertial sensor. It fuses accelerometer and gyroscope data in real time to estimate device orientation, detects reps and sets automatically, and uses an Edge Impulse machine learning model to classify which exercise is being performed.

## What It Does

* Reads raw accelerometer and gyroscope data over I2C from an MPU6050
* Calibrates sensor offsets and gravity bias on startup
* Fuses gyroscope and accelerometer readings into a quaternion based orientation estimate, with a complementary filter correction term to keep the estimate anchored to gravity
* Detects movement versus pause to automatically segment reps and sets
* Feeds a rolling buffer of motion features into an Edge Impulse classifier to identify the exercise being performed (for example bicep curl or lateral raise)
* Streams live JSON telemetry over serial, including the predicted exercise, confidence, rep count, and set number
* Includes a Python logging tool for capturing labeled training data used to train the classifier

## Project Structure

| File | Purpose |
|---|---|
| `main.cpp` | Core firmware loop. Handles calibration, sensor fusion, rep/set detection, and classifier inference |

| `README.txt` | Documentation generated by Edge Impulse for the exported inferencing SDK and model library |

## How It Works

### 1. Calibration
On startup, the device samples the gyroscope and accelerometer at rest to compute bias offsets, then computes the expected gravity vector for the starting orientation so gravity can be subtracted from later readings.

### 2. Sensor Fusion
Orientation is tracked as a quaternion. Gyroscope rates are integrated over time, and a correction term derived from the cross product between the measured and expected gravity vector nudges the estimate to correct for drift. A high pass state is used to freeze the integral correction when the device is nearly stationary, preventing small noise from accumulating.

### 3. Rep and Set Detection
Accelerometer samples are averaged and tracked over a rolling window. Extended periods with little to no motion mark a pause. Sustained motion increments a half rep counter, and full reps and completed sets are derived from that count. A long pause after an active set closes the set and resets calibration for the next one.

### 4. Exercise Classification
Adjusted acceleration, gyroscope, pitch, and roll values are pushed into a circular buffer. Every few samples the buffer is fed into an Edge Impulse classifier (`run_classifier`), which returns per class probabilities. Votes for the winning class are tallied across the set, excluding an idle class, and the most frequent non idle exercise is reported when the set completes.

### 5. Data Logging for Training
`imu_logger.py` connects to the device over a serial port, prompts for an exercise label and set number, and streams incoming CSV rows (accelX, accelY, accelZ, gyroX, gyroY, gyroZ, pitch, roll) into a labeled file under a `training data` directory. This data can be used to train or refine the Edge Impulse model.

## Hardware Requirements

* Microcontroller running Arduino or Zephyr firmware (see `CMakeLists.txt` for Zephyr integration)
* MPU6050 accelerometer and gyroscope, connected over I2C
* Serial connection to a host computer for telemetry and data logging

## Building

The firmware targets an Arduino style build for the sensor and workout logic, with the Edge Impulse inferencing SDK integrated as a Zephyr module through `CMakeLists.txt`. Add this library to your project and ensure a target named `app` exists before including the CMake file, per the SDK's own setup instructions in `README.txt`.

## Running the Logger

```
python imu_logger.py
```

You will be prompted for an exercise name and set number, then asked to press Enter before recording begins. Data streams to a CSV file until you stop it with Ctrl+C.

## Model

The classifier is trained through Edge Impulse under the project fluxGrip. See the Edge Impulse studio link and documentation referenced in `README.txt` for deploying an updated model as a C++ library.

## Status and Notes

This is an active work in progress. Sensor fusion constants (such as Kp and Ki) and pause thresholds have been tuned experimentally and may need further adjustment for different devices or mounting positions. Some legacy or experimental code paths (such as low pass filtering for impact detection) are present but currently disabled.
